# ADR039：独立 DSH 适配边界与已验证版本矩阵

2026-11-02，T040 / Issue #93，基线 a6743140957257a2991507de658bdc433b573cd3。用户明确要求同时补多版本兼容测试与独立 DSH 适配层。本设计先于实现提交。

## 决定

1. 经验、来源验证、SQLite v9、预算和授权继续使用现有核心契约，不导入 DSH SDK。工具/会话/Agent 事件、模型准备与流、原生认证通信、页面注册集中在 `dsh-adapter-*` 模块。既有公开入口保持，核心不感知宿主版本；版本差异只能进入适配边界。
2. 首轮目标是官方 `0.2.0-rc.2` 与截图中 Desktop 的 `0.2.1-rc.5`。逐个检查真实 SDK 类型与行为，不通过自造宽泛 any、替换宿主实现或绕过预检宣称兼容。若差异阻止某项能力，记录缺口并继续适配，不把安装成功当作学习验收。
3. 支持清单集中维护，包的精确版本并集与清单一致。预发布版本不使用 `*` 或未经验证的连续范围；新版本须先通过矩阵再加入。适配入口拒绝未知宿主版本；同一 profile 使用一致的 DSH SDK 家族，不运行新旧实例共同操作原库。
4. 构建并审计一个未发布的 `0.1.0-alpha.2` 候选包，再在隔离源码副本中切换固定 SDK，进行两版本类型检查/契约/原生页面/安装与零模型学习验收。切换工具只改临时副本中的开发 SDK，不改产品 peer 范围、不隐藏兼容异常；两个宿主安装同一原候选包并逐产品 JS 校验。Windows/Linux CI 都覆盖两个版本。
5. 回归包括工具与会话隔离、直接用户来源/子任务拒绝、取消与卸载、模型路由和输出限额、原生认证/repoId/revision/32KiB边界，以及 profile 同库重启后的经验/应用/反馈、用量指纹、已用 grant 和 unknown 不变。脚本模型仅作协议验证，付费调用为零，不证明真实模型质量或未来任务收益。
6. 根 lockfile 固定一个基准 SDK 用于可重复构建；矩阵的第二版本在 ignored 副本中以明确版本安装。适配层边界有静态检查，禁止 SDK 依赖回流核心。记录两版本官方包来源、实际失败与修复、矩阵结果和后续加入版本步骤。
7. 原 alpha.1、注释 tag、冻结 tgz 与 Release 附件保持不可变，历史审计必须准确匹配原版本和摘要。新版源码、候选包、公开发布分开。本轮只开发/验证并准备候选；未经新的明确授权不执行 npm/Release 发布，不改变当前 Desktop/profile、凭据或私人学习库。

## 验收与边界

先设计、保留真实失败，再实现。目标矩阵在固定官方组件与实际包中执行，另检查独立完整宿主的加载与可用入口；不把组件测试说成完整 Desktop 应用 E2E。适配后应减少接口变更对核心的影响，不能保证任意未来版本兼容。稳定 SHA 独立只读审查、当前头必要 CI、文档与仓库规则满足后交付；实际结果及未完成范围写入任务验收/Issue，不提前计通过。
