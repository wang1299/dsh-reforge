# ADR056：有界Agent修复回合、独立验收与真实尝试计数

2026-11-09，T062 / [Issue #137](https://github.com/wang1299/dsh-reforge/issues/137)。先于实现。T061的题目控制与输入送达不是模型修复；本增量推进真实研究所需的执行控制器，不改变题目/策略/验收，不声明已实现付费执行。

## 修复控制器

- 沿用已冻结v1.1的6题、3条独立来源策略、36项顺序和统一任务/Schema/系统/256字符查询；不看模型结果换题或补关键词。来源验证与任务收益仍分开。
- 每个trial使用新的官方AgentLoop上下文，最多2个显式用户修复回合，每回合恰好1个请求、2048输出上限、温度0、无模型工具。第一回合返回单个JSON对象`{"code":"完整repair函数"}`；不是模型自评。controller在准入后写入本trial合成文件并运行仓库外固定pytest。通过则结束；可确认的生成/验收失败才允许一次预先规定的修复回合。异常/断流/不完整回执归未知，不自动重放。
- 第二回合只回传固定状态码和有界测试ID/状态，不给测试源码、参考修复、断言预期或任意pytest输出；原任务契约和原始函数在同一上下文中。不能把未知执行变成已知失败来自动再调用。
- JSON形状、UTF-8字节上限、AST准入、实际系统文本/参数、请求数、候选验收和结束原因分别检查。AST用于固定合成函数，不是通用恶意代码沙箱；未来不能直接放开真实仓库任意代码。
- 保留每回合是否实际请求、输出/代码摘要、验证状态、测试ID/状态、耗时与有界合成提案文件；不保存完整会话或原始模型响应。错误解析/超限/非法语法不执行。没有有效pytest回执不算成功。
- 报告first-pass、final-pass、实际attempts/rework、无效生成、失败/未知、已计划与实际完成分母。模式必须区分脚本演练与真实模型，脚本使用作者参考答案只能说明控制器工作，不是Agent能力/省钱/收益。费用暂不适用，不能伪造usage或提供真实模型成功率。

## 本增量的零费用入口

入口只有显式脚本rehearsal，固定内部脚本adapter，不加载凭据/付费endpoint或旧账本；不存在用旧T049授权启动的live参数。复用的T061合成来源/选择辅助接口只为新研究服务，不改变插件默认行为或已有数据。新工件仅写本仓库`.probe-work`新目录，旧记录不覆盖。

预先固定脚本模式：首轮参考修复、原始错误→参考修复、一直错误、声称成功但没有JSON、非法代码、传输不完整。真实SDK/pytest探针核对：首轮正确仅1次；修复成功恰2次；错误/自述不能通过；非法函数不执行；未知不自动重试；错误第二轮不泄露测试/参考答案；各trial不继承前一个会话。

## 后续真实调用门槛

仍须实现并独立审查新的持久费用占额、每次HTTP前授权/冻结检查、无自动重试、完整usage回执、未知停机和不可重放的一次性研究状态；核对当前官方价格，冻结实际执行依赖/源码/候选包与模型版本。授权绑定新研究和计划，不能复用T049已完成的10元上限。只有形成完整可审查的真实执行结果/预算方案后，再请求新预算；未授权前不读Key或发付费请求。

本设计不修改主SQLite v9/预算/提炼次数，不发布npm、Release或官网。完成该控制器不结束持续UX与真实收益目标。

实现后的付费前独立审查修正（先补设计再实现）：目标写入由runner/controller共用安全写入器，拒绝contract/target符号链接、联接和nlink>1，读取哨兵使用描述符及身份核对，候选以独占新文件写入/同步后原子替换，不跟随既有目标链接写原inode，也不在Windows替换失败时回退截断。它防止本试验误写已有链接，不宣称抵抗任意恶意并发文件系统操作。

AST验证改为完整、固定的accepted/rejected回执：只有受控解释器正常结束且明确rejected才算已知invalid_code；缺失解释器、超时、坏回执/启动失败均unknown并终止，不触发第二次请求。补禁止未绑定危险Name和调用目标重绑定的alias反例；JSON重复/转义别名键拒绝。真实live仍需独立进程/文件系统限制，不能把AST当安全沙箱。数据绑定沿用实际JS入口及相关选择源码起止摘要、runtime/method记录，仍不冒充完整live依赖冻结。
