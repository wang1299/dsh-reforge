# ADR054：工作台任务输入、owner条件和正常模型前置核对

2026-11-06，T060，[Issue #133](https://github.com/wang1299/dsh-reforge/issues/133)，基线main `a0fc04ddc515699d9f330441db6f0a538a0130f3`。持续目标仍包括实际Agent收益；本轮不能用脚本传输检查替代它。

## 真实时序与设计选择

当前官方agent/pre-step在automatic.begin后立即context/select，并按片段缓存结果；模型后再补表单不会改变第一次输入。采用“填写任务/Schema/属性/明确目标→只读预览→owner确认并提交当前对话”流程：认证宿主创建真实UserMessage取得不可伪造的当前消息ID，先持久保留一次提交回执，再调用正常Agent.followup。不是为任意下一条消息挂模糊的待用授权，不读取全会话历史来猜目标，不唤醒已有pending inbox。

仅当前对话的原生经验页可提交：官方operator/browserPeer身份、配置仓库、非seed/subagent、相同Agent实例/模型配置、idle且nextTurn/nextStep为空、shareWithModel均需满足。idle只表示可接收输入，不证明任务成功。主插件页/设置页/独立HTTP面板可做文件预览、管理owner条件和核对回执，但没有Agent时不能假装发送成功。任务提交会使用当前对话模型，UI必须在确认按钮附近说明可能发生该模型费用；本轮工具和演练只用零HTTP脚本适配器，不提交真实付费任务。

实现前独立审查修正：官方status=idle也可能由maintenance占有。submit必须通过公开runMaintenance取得真实空闲阶段，在同一个无额外await的同步段重查实际Agent/模型、取消信号、空inbox、预览和权限，再reserve/消费预览/followup；不能仅靠展示状态。若已有maintenance/turn则在reserve之前拒绝；followup在本次维护段内排入由该段释放后唤醒的正常下一回合，不抢占其他维护工作。

## 来源与条件

复用冻结T059的有限Schema读取器，不改其源码/数据/模型/方法。新的在线协议使用repair_behavior/validate_payload/change_contract/present_ui/generate_docs五种明确目标，其中repair_behavior是正常修复的新增类别；不把旧四目标比较冒充新在线方法效果。

旧经验没有条件，不自动推断/迁移。owner在工作台为一个确切经验版本声明：Schema相对路径、属性、从展示的三事实中明确选取的有限前提，以及允许的目标。来源预览和owner条件声明分别标识；这不验证策略语义，不提升source_verified。经验修订后旧条件保持为stale，需要重新声明，不能悄悄失去保护。

在线选择保留现有来源/版本/仓库/依赖/代码/反馈资格及完整原排名。只对原本第一候选增加owner条件veto，拒绝后不搜索其他候选补答案、不改变BM25语料/分数。无owner条件且非准备任务时保持旧行为；准备任务仅允许明确声明过条件的经验。已有条件但缺本任务事实/目标、条件过期/来源变化、目标矛盾或配置无法读取时保持空参考。条件和目标用新任务身份绑定的fresh字节核对，不复用旧票据/跨会话事实。

## 数据与一次提交

保留原SQLite v9和所有经验、预算、unknown与授权。新增独立、延迟创建的`owner-inputs-v1.sqlite`（sidecar schema1），与原插件数据目录一起停机备份：最多64个owner条件、128个有界提交回执，过限拒绝或仅清理终态旧回执。另保留最多4096条紧凑owner消息/任务分类（无请求原文），不随回执淘汰；达到分类上限在提交前拒绝，不能删分类来绕过禁止学习/重放边界。SQLite事务/CAS处理并发，不用迁移的PID锁文件。配置格式/仓库不匹配或损坏时不自动重建/清空，也不能回退绕过已有保护。原v9的user_version、表及财务逻辑不变。条件只由支持本协议的新进程执行，不与不理解这些规则的旧插件混用同一数据目录。

预览只读，最多64个短期内存预览、120秒有效。原始单次任务文字<=2000字符仅在UI/短期预览和DSH正常消息中存在；沿用v9任务记录最多256字符脱敏摘要的明确例外，新入口调用begin时也先限256，不能把完整2000字符另写入插件库。sidecar只存文字摘要hash、源路径/摘要/属性、明确目标、消息/任务/会话身份、条件修订及有限事实/状态，不另收集完整会话、注解/default、凭据或工具原文。UI需如实说明正常DSH会保留其自身对话，以及本插件保留有界脱敏任务摘要。

submit带服务实例ID、预览ID、请求UUID。相同请求只返回同一回执，不再次followup；不同内容同键拒绝。持久reserve先于enqueue，enqueue失败/回执中断保持unknown，不自动重发。重启使旧实例预览无效，旧未终结回执不当作可重放任务；不得仅凭实例不同抢占另一个活进程。能确认创建进程已结束时，只关闭本入口创建的未关闭任务并保留unknown，不接续执行，不处理无对应本入口回执的旧任务。

幂等保证以有效回执为界：reserve成功即一次消费预览，早于enqueue；同预览换新UUID也不能发送第二次。回执已淘汰、预览过期/已消费时只能拒绝旧请求，不承诺无限期返回同一回执。永久消息/任务分类使缺失回执的旧消息仍被识别为本入口未知数据，不能掉回旧选择/学习路径。

预步骤只接受恰好一个直接用户消息、同一实际消息ID/会话/Agent实例。自动学习开启时沿用既有片段/歧义/执行授权；关闭时只建立本入口明确提交的正常任务，在turn/end关闭，不排队学习/验证/提炼。新入口不增加执行或学习授权。主任务建立与sidecar绑定需按固定顺序在主库外层事务内衔接；跨库异常不能变成已确认送达或可自动重试，重启不留下可重放的未知任务。中途steering/取消不复用已缓存的owner输入。

持久context_only分类必须覆盖service.finish、correction/propose/verify/link/recovery及对应入队路径；本回合模型不能用evolve_begin_task另开手动任务绕过，也不能靠notice要求模型自律。正常turn/end、工具finish、显式候选/验证与回执淘汰/重启后均检查同一分类；历史普通手动任务保持原行为。源版本过期探针需让新经验版本仍有完整来源资格，再独立验证owner revision veto。

两库不宣称原子：主库外层事务包住新任务建立与sidecar任务分类绑定，可出现sidecar已绑而主库回滚的孤立记录。该记录缺实际任务/身份摘要不匹配时一律unknown且不可重放；不能把主库事务当成跨库提交。绑定前先持久保留消息分类，提交任务后不得删除它来使旧消息成为普通新任务。

facts/goal先绑定实际taskId、修订、repo，再在经验选择前使用；返回的owner上下文只含有界数据，作为单独notice进入真实模型输入。回执“绑定/回合结束”均不代表模型采用或任务验收；现有Application仍仅是参考选择记录。已发出的历史模型上下文不能被事后抹去，不声称模型忘记历史，只保证插件不再为另一任务取用同一活动票据。

### 存储审查后的身份约束

独立存储审查发现，仅按repo_id过滤会把误配的外来sidecar解释成未配置，实例内seenFile也无法检测重启前丢失的文件。因此新owner元数据明确绑定单个仓库；默认dataDir本已按repoId隔离，自定义共享目录不能复用另一仓库的owner配置。新增同目录有界`owner-inputs-v1.identity.json`，只含格式标识、repoId和随机storeId，SQLite格式头必须精确匹配。首次写入先独占创建身份锚，再创建SQLite；中途失败保留可诊断的不完整状态，不自动重建。锚或SQLite单独丢失、身份不符、外来仓库与损坏均失败关闭，重启不能把它们当作无条件的新库。

完整停机备份须同时保留主库、sidecar和身份锚。两份owner元数据均被手工删除或整套替换无法凭现有v9主库区分初次安装，不承诺抵抗这种目录级篡改；本轮不修改主库格式或新增主库锚。此限制需出现在运维说明与测试边界中。

## UI与量化验收

沿用Tabler四视图、已有搜索/详情。任务准备与经验条件编辑采用稳定表单、明确目标选择、先检查再确认、来源/条件/模型提交分层反馈；轮询不覆盖草稿/抢焦点，未知结果不自动重试。新原生请求从外层实际sessionId解析宿主能力，不能让iframe payload自报身份/伪造模型载体。独立面板明确显示提交能力限制，所有新HTTP操作仍要token、同源JSON；原生仍用官方认证carrier。

先提交新的固定工作流场景，再实现。场景分为预提交拦截、实际运行时选择、幂等/恢复、默认行为；未提交的输入不能被统计成检索正确拒选。实际官方AgentLoop/脚本adapter检查正常输入顺序、真正GenerateOptions中的数据、选择/拒绝及一次提交，不以idle/transport/model自报算任务成功。至少正向修复、UI目标、条件矛盾、已提交后来源变化和重复请求走真实宿主；其余安全/恢复场景用实际API/存储验证。共用一份真实pytest来源证明的场景不能称独立策略或真实用户样本。

新协议与T059已用留出分开；报告请求/提交/模型前提供/错误提供、漏选/信息不足和owner输入项/操作数的真实分母，不把额外人工确认叫语义模型提升或真人省时。真实模型成功率/返工/成本另做新预登记与预算授权。

要求针对测试、实际原生/独立浏览器与390px/键盘/轮询、完整check/compat、两宿主Windows/Linux同包矩阵、独立稳定SHA只读审查后合并。不发npm/Release/部署，不碰真实私人profile/Key/旧账本或自动重放未知任务。若输入/条件/实际模型路径仍未贯通，Issue #133不能按全项完成关闭。
