# ADR055：新任务收益研究的题目、输入与验收预检

2026-11-06，T061 / [Issue #135](https://github.com/wang1299/dsh-reforge/issues/135)。先于实现提交。基于 T060 源码；PR #134 的合并/官网部署授权仍待回复，不改其冻结提交。

## 要解决的问题

T049 三组均4/4，但实际经验提供均0/4，不能回答经验的收益。T060 的6项脚本工作流也不能回答真实模型任务成功率。下一轮必须先确认新题确实失败、验收能区分正确/错误修复、三组实际模型输入中的经验送达，并预先记录对照方法。

## 固定设计

- 新的6项作者可见合成任务，3个任务族：字典批量变更的失败原子性、消息投递/幂等重试、缺省/显式null/零值。每族2题；不是盲测或模型训练集未知。
- 3条作者撰写的策略，各自对应独立原始失败、修复通过、回归通过的来源证明。与 T049 的真实模型自动提炼分开；来源证明不能证明策略在目标题中正确。
- 目标题不进入来源验收。每题的任务契约明确说明行为，外部pytest检验原始失败、参考修复通过、一个有意不完整/错误迁移的修复失败。参考修复和测试代码不能进入模型请求。适用标签是事先作者判断，不是Agent验收。
- 三组 none / plain / reforge。相同任务、原始代码、Schema、目标、系统说明和工具/生成限制；只有经验选择及相应片段不同。plain 对同一来源库做当前BM25词项检索；reforge 使用当前实际服务、原始首候选和owner条件否决，不强制选中或补选。任务词项和策略在任何真实模型结果前固定；预检暴露的检索缺项如实保留。
- Reforge任务用实际owner提交/绑定路径获取当前notice。评测请求只投影其中的经验payload，公共工程事实已在三组相同任务中提供；不把仅给Reforge的额外契约混入比较。preflight清楚标为“选择路径→统一输入封装→实际脚本GenerateOptions”，不是完整Desktop或生产host端到端对照。
- 独立新上下文、两次重复、每题六种组顺序轮转：6题×3组×2轮=36项计划。首次通过、最终通过、实际修复轮数/人工编辑、耗时、经验提供/拒选/版本、完整计量/未知占额、总费用及各失败必须保留。小样本按分子/分母与逐题配对展示，不承诺显著性或提升。
- 本增量只做前置预检：真正AgentLoop使用不联网的脚本adapter，固定说明没有修复；不将作者参考修复当作模型生成或成功率，不计算伪token/费用。零HTTP不是付费链路验证。

## 持久化与运行边界

数据、方法和原始实现摘要进入有界的准备报告。新合成工程、来源库与临时pytest工件仅在本仓库 `.probe-work` 的新目录；不读取原profile、历史SQLitev9数据/账本、凭据或环境Key，不覆写旧研究。只保存结构化计数、测试ID/状态、经验/应用ID及摘要；不保存完整会话、任意工具输出、生成的认证网址。

入口仅接受 `prepare`，没有live选项/HTTP模型实现/认证解析，不接旧 `PilotBudget`。新真实执行还需：同模型固定实现与独立验收/有限工具回合、冻结执行依赖和候选包、新的独立费用账本及明确预算授权、官方当前价格核对、未知占额停机及不自动重试、稳定SHA审查。不得因本次预检成功重用旧10元授权。

## 验收和后续

预检必须显示所有原始失败、参考修复通过、错误修复失败，以及实际脚本请求中的逐项经验送达。拒选或错误选择是结果，不能为得到绿灯而强行改为提供；题目/策略修订必须新版本并保留原版。

本次不修改默认选择器、学习/存储协议、用户界面、授权或发行物，不发布npm/Release/官网。完成题目和输入预检只是推进下一轮真实验证；实际Agent收益仍未证明，持续目标不在此结束。
