# ADR061：有界并发运行清单与耗时说明

2026-11-09，T067 / [Issue #147](https://github.com/wang1299/dsh-reforge/issues/147)，基于T066提交55d7089。先于实现。上一轮为实际源码交付进展：PR #146已完成四组合CI、实际安装、浏览器和只读审查，尚未合并或发行；持续UX和真实效果目标仍未完成。

## 依据

T065的真实trial阶段416.521秒，其中guard320.755秒、provider请求至完整响应49.500秒；guard约占77%。这些边界不等于纯模型推理，夹具和不同请求数的耗时也不能用于宣称模型提速。当前清单逐项等待realpath/lstat/readdir；内容hash已经每批最多16项并发。本轮只优化重复清单核对并让用户看懂耗时，不把工程加速替代经验收益验证。

## 决策

- 每次核对仍重新枚举全部根、路径、父目录实际位置、文件身份及大小/时间。不给metadata或realpath增加跨路径/跨次缓存，不减少任何独立路径的准入检查。root顺序保持，重叠路径仍以最后一个root的group为准。
- 同一root使用最多16个活动walk的队列，每个walk内部保留原检查顺序。每root按解析后的精确路径去重排队（原清单最终也按路径唯一）；去重不跨root或跨次核对。排队独立路径和最终条目都不超过40000。跳过字段、私有配置名、目录别名、叶链接/target闭包、硬链接、单文件/总字节边界、critical覆盖、起止全hash与逐次critical hash保持原谓词。最终清单排序和version1格式保持。
- 首个失败停止派发新项，等待已经派发的有限工作结束，再拒绝；不产生后台悬空任务或未处理的拒绝。并发清单仍不是原子文件系统快照；信任owner/OS、不抵抗rollback的边界保持，变化拒绝而不更新baseline。
- 保存55d7089的串行实现为开发专用oracle。对同一不变fixture比对完整清单、摘要和拒绝判定；同时测试新增/删除/替换、链接/中间别名、私有文件、critical缺失、重叠root和错误排空。oracle不作为运行时fallback或新实现的自校验器。
- 零费用benchmark交替串行/并发顺序，分别报告1000/10000文件合成树和当前公开运行闭包的独立核对耗时分布、完整hash耗时、实际条目/字节及manifest一致性。固定16并发，不从付费试验结果调参。不读旧profile/私人结果或Key，不改旧账本，不运行模型；小样本本机性能不宣称跨平台泛化或纯模型延迟提升。
- schema1本机报告投影新增可选timing：elapsedMs、guardMs、providerMs均缺失时明确未知；出现则要求三者为有界非负整数、guard+provider<=elapsed。显示“运行检查 / 请求与完整响应 / 其余流程”，不推测其余流程的具体组成。现有Tabler风格下用可折叠说明和文本/比例条，无额外依赖/上传/执行/授权能力，旧报告不回填、不改写。清除时连同时间与摘要投影移除。
