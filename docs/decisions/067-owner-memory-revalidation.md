# ADR067 — Maintenance of verified repair memories

The T074 review identifies drift and recommends another verification. T075 connects that finding to the existing authenticated owner panels. The owner selects one experience, inspects the proposed revision and Git commit, then explicitly requests a local pytest replay. The model has no maintenance tool.

- Read-only review groups page-local references to the same historical verification after checking source identity and complete fact citations. Shared evidence says nothing about equivalence of advice. Keep every original experience, citation and counterexample.
- Replay applies to a closed manual Git source with complete provenance, an explicitly trusted execution policy, changed committed code conditions, the original external acceptance suite and the same dependency scope. Other changes need owner investigation. Use Git blob bytes for the commit binding, including dependency manifests; fail closed if the working copy differs.
- Before running tests, atomically append a candidate with the current scope, the original historical fact citations, and no verification. Compare the selected revision, commit and historical proof. A stale or repeated request cannot start a second run for that revision. Keep all historical records.
- Run the existing original-failure, fixed-acceptance and regression verifier. Check the tested commit, conditions, acceptance digest, regression coverage, provenance and current candidate again before saving a fresh result. An inconclusive or interrupted replay retains a candidate. A newer owner edit wins. Do not replay automatically after interruption.
- Return only bounded identifiers, fixed decisions and revision metadata. No new grants, provider requests, database schema or hosted service. A passing replay establishes source evidence for one repair in this environment. Task benefit requires a separate controlled study.

Design references include [Anthropic's knowledge wiki](https://github.com/anthropics/claude-quickstarts/tree/main/managed-agents/knowledge-wiki) for preserving provenance and disagreement, and [Microsoft Agent Framework's memory implementation](https://github.com/microsoft/agent-framework/blob/main/python/packages/core/agent_framework/_harness/_memory.py) for separating extraction from consolidation. Implementation uses Reforge's existing SQLite history and independent Python verifier.
