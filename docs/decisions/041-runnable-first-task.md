# ADR041：可复现的首次任务示例

2026-11-04，T047 / [Issue #106](https://github.com/wang1299/dsh-reforge/issues/106)，上级 [T046 / #105](https://github.com/wang1299/dsh-reforge/issues/105)。先于实现提交。

提供源码入口 `npm run example:customer-form -- --python <executable>`，对应公开视频中的“保存失败不丢输入”。入口只接受 Python 可执行文件；不接受业务仓库、配置、凭据或已有数据目录。每次在本仓库忽略的 `.probe-work` 中创建唯一的新工程、外部验收和独立数据库，不复用或重置旧演示。需要 Node ≥24.10、Git、Python ≥3.10 与 pytest；缺失时报告本机修复步骤，不自动安装或更改账户。

示例使用合成客户资料、预先公开的补丁和真实服务方法。明确纠正 → 候选引用 → 原始版本两项失败 → 修复版本两项通过 → 三项回归通过 → 一条来源验证经验。固定外部验收不在受修复工程内。没有模型、自主编码、自动提炼、授权增加或未来收益评价。仅对新建的受信任合成工程允许 pytest；共享、后台验证和自动学习均关闭，不创建提炼授权。

本机 Web 只监听随机 loopback 端口；检查 Host、同源 JSON、请求大小和严格输入；序列化写入并限制阶段，拒绝重复验证。Python 子进程有超时和输出上限，参数不经过 shell。页面只展示合成差异和计数，独立工作台沿用已有令牌认证。退出先等待活动操作结束，再关闭面板和数据库。失败或未知操作保留现场，不自动重复提炼或验证。

示例源码、固定验收与运行说明随 GitHub 源码提供，视频不打入 npm；安装用户从源码示例入口开始，不能把已发布 alpha.1 说成 alpha.2。用户导航区分快速体验、正式配置、排障、数据运维、评价和开发历史。新增 issue 表单与安全指南只规定有限、脱敏信息，不索取数据库、会话、认证地址或 Key。

验收使用真实隔离 Git/pytest/SQLite 和 HTTP 边界测试，并运行当前静态、完整、兼容检查及两宿主双平台 CI。稳定 SHA 独立只读评审通过后合并；本任务不独立发布安装包。T046 中真实模型验证、收益与发行分别记录，不从本示例推导。
