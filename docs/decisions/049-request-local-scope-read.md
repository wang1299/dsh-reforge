# ADR049：仅在同一次选择内复用新读取的仓库状态

2026-11-06，T054补充决定，先于实施提交。索引接入源码 `42375f0b7fb7b76922369e4bd119b3bdb4d7b1c6` 的首轮实际链路测量显示：只复用文本索引没有整体收益；1条P50 292.41→291.05ms，10条1476.96→1491.26ms。保留原始JSON，不调样本或隐藏变慢。

瓶颈是同一同步 `select` 内为任务归属及每条经验重复执行Git根/HEAD、依赖读取与相同条件文件哈希。选择如下：

- 私有任务归属检查返回刚读取的完整仓库快照；公开 `requireTask` 的签名、验证顺序与返回保持，调用者不能注入快照跳过验证。
- 同一次选择用此快照的仓库/依赖状态，按路径读取并验证各经验所需文件；每个条件文件读一次，失败也只影响依赖该路径的经验。所有路径仍用相同 `safeFile` 边界，不能将某个缺失文件误当整个库失败。
- 每次 `select` 新建读取器，调用完成后不保留；不跨请求复用仓库、依赖或文件资格。经验状态、来源证明、事实引用、反馈仍重新读取，索引依旧只在本轮合格集合一致时复用。
- 这是请求内一致的读取视图，不是文件系统原子快照，也不能防止外部进程在检查之后改文件。既有验证边界不扩大；不绕过来源/权限，不把稳定文本分数视作当前资格。

内部对照端口区分原版逐经验读取、仅索引复用、索引加请求内读取三组。正式三组测量源码先提交，之后同一新合成库/查询交错比较，完整保留冷请求、原始样本、分数/选择/拒绝一致性和任何负结果。记录本次选择实际仓库快照调用数（含任务归属）、条件文件读取数及阶段耗时，不能把查询微基准当整体收益。

验收增加：无跨请求状态复用；共享数据库及文件/依赖/停用/反馈变更继续阻断；同一请求中的缺失路径不影响其他合格经验；1条/10条实际服务链与原版相同，报告所有三组结果。只改变读取组织，不改BM25、资格谓词、SQLite v9、授权、费用或模型调用。
