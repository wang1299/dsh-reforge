# Agent 收到具体拒绝原因后，能修好什么？

在一个批量投递任务里，Agent 要逐条发送并记账。第二条发送失败时，第一条应保留为成功，失败的那条要能重试。我们在同一个公开任务上做了四组配对，检查两件事：Python 拒绝的具体原因有没有进入 Agent 的下一次请求，以及改写后的代码能否通过独立的行为测试。

| 同一份首轮提案 | 仅有通用拒绝的最终结果 | 多给一条具体诊断的最终结果 |
|---|---|---|
| 投递逻辑正确，返回列表时使用不允许的列表推导式 | 再次被拒绝 | 改写返回语句，两项测试通过 |
| 使用相同推导式，还在发送前提前标记成功 | 再次被拒绝 | 通过语法检查，部分成功后重试的测试失败 |
| 使用脚本没有对应改写的切片 | 再次被拒绝 | 再次被拒绝 |
| 合法且逻辑正确 | 首轮通过 | 首轮通过 |

两组各运行四个独立会话，各收到七次脚本模型请求，各有三个会话进入第二轮。第二轮通过数分别为 **0/3 和 1/3**，最终通过数为 **1/4 和 2/4**。通用组有一次提案进入 pytest，具体诊断组有三次。未知结果为零，模型服务请求为零。

## 从源码复跑

使用本仓库源码、Node.js 24.19.0 和装有 pytest 9.1.1 的 Python 3.10。默认使用 `python`，也可将 `EVOLVE_PYTHON` 指向该解释器。

```shell
npm ci --ignore-scripts
npm run study:feedback
```

终端显示每组的计数、核对结果 `qualified` 和本地报告路径。每次使用新的目录。报告中每对的 `inputs` 是适配器实际收到的请求内容摘要，`retry.diagnostic` 是该适配器在重试消息中读到的诊断，`attempts[].cases` 来自 pytest 的测试结果。核对失败时命令返回非零退出码。如果 Python 不可用，该轮标为未知并结束会话。

## 如何解释这个结果

每组都使用相同的 DSH AgentLoop、首轮提案、静态 Python 规则和最多两轮的预算。两组始终执行真实的语法准入，独立测试位于合成工程外。脚本只会根据上一轮自己的提案和收到的规则名、节点类型改写一种列表推导式。配对核对包括首轮请求内容、首轮提案，以及从第二轮请求中移除具体诊断后其余内容的摘要。

这是对反馈传递和脚本行为的验证。Python 检查由控制器调用，研究协议中没有模型发起的原生工具调用。四个样例是为验证不同分支而编写的，属于同一个任务。历史实验缺少触发拒绝的语法记录，真实模型能从具体反馈中受益多少仍待单独检验。[首次真实实验](benefit-live-20261109.md) · [本次设计](../decisions/069-feedback-comparison.md) · [另行规划的三组复验](https://github.com/wang1299/dsh-reforge/issues/153)
