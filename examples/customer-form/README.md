# 客户表单：保存失败不丢输入

[English](README.en.md) · [文档导航](../../docs/index.md) · [同款视频](../../docs/demos/first-task.md)

这是视频中的完整合成工程。真实运行 Python、Git、外部 pytest 和 DSH-Reforge 服务；补丁预先提供，不需要 DSH、API Key 或模型调用。

## 启动

在本仓库源码根目录，使用 Node ≥24.10、Git、Python ≥3.10：

```sh
python -m pip install pytest==9.1.1
npm ci --ignore-scripts
npm run example:customer-form
```

Windows 可用 `py -3.10 -m pip install pytest==9.1.1`。Python 路径不在 PATH 时：

```powershell
npm run example:customer-form -- --python 'C:\path\to\python.exe'
```

终端显示客户表单地址、私密经验面板地址和本轮目录。打开客户表单地址，保留启动终端；Ctrl+C 停止。完整面板地址含本机访问令牌，只在本机使用，勿贴到 Issue。每次启动创建新案例，不复用旧案例。

## 跟着视频操作

1. 填入演示姓名、测试电话和备注，保持“模拟保存服务不可用”开启，点击保存。**修复前输入丢失**，这是待修复问题。
2. 切到“修复与独立验收”，记录明确纠正，再应用实际修复。按钮只修改本次合成工程中的 `form_state.py`，并提交该工程的 Git。
3. 回到表单，重新填写演示数据；失败时应保留全部输入。关闭故障注入，再保存，成功后才清空。保存中按钮防重复提交。
4. 点击“验证修复并保存经验”。固定的仓库外验收分别运行在原始与修复版本，随后执行仓库内回归。
5. 打开终端中的经验面板，查看一条通过来源验证的经验、纠正来源和版本；此时应用记录 0、反馈 0、模型调用 0。

| 检查 | 预期结果 |
|---|---|
| 原始版本外部验收 | 2 项失败：失败保留、成功后清空时机 |
| 修复版本同一验收 | 2 项通过 |
| 仓库内回归 | 3 项通过 |
| 来源验证经验 | 1 条 |
| 模型提炼与未来收益 | 未执行、未评价 |

来源检查不通过时保留候选和原因，不强行显示成功。验证只允许尝试一次；失败或连接中断先检查保留的现场，不能盲目重复。重新启动入口会创建一个全新的案例。

## 文件与数据在哪里

- `before/`、`after/`：公开视频对应的原始与修复函数。
- `project/`：不变的适用条件和三项回归；生成工程时加入原始函数。
- `acceptance/`：两项独立验收，复制到生成工程之外。
- `app.html`：合成客户表单和显式记录界面（中文）。
- [启动实现](../../scripts/customer-form.ts)：只操作本仓库忽略目录 `.probe-work/customer-form-*` 下的新工程。

本轮目录保留 `project/`、`acceptance/`、`config.json`、`data/` 和验收后的 `result.json`。本地报告包含合成测试结果，不是公开收益报告。服务停止后可用 `node dist/src/cli.js panel --config <本轮config.json>` 重新查看；只重新开面板，不接续或自动重放工作流。

使用合成信息，不填写真实客户或凭据。数据不会提交 Git；旧项目、原经验、预算和授权均不参与本例。清理时先停止服务、确认目标是自己不再需要的特定合成目录；没有自动删除命令。

## 遇到问题

缺 Python/pytest：按上面步骤安装到同一个解释器，并显式传入路径。缺 Git：安装后重开终端。网页连接被拒绝：服务需保持运行，重新启动后使用新地址。验收失败：保留本轮目录，仅报告版本、失败阶段和脱敏计数；不要上传数据库或完整日志。
